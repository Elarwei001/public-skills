# 树状结构原则：如何让 AI 处理复杂任务

> 来源：Matthew Schwartz (Harvard Physics) 的 "Vibe Physics" 实验
> 他用 Claude 两周完成了通常需要一年的理论物理论文。

---

## 核心原则

```
大任务 → 拆成小模块 → 每个模块独立可验证 → 根部有全局规则
```

## 问题：为什么长文档会失败？

| 问题 | 后果 |
|------|------|
| **上下文压力** | 每次修改都要加载整个文档，token 爆炸 |
| **注意力稀释** | AI 容易"忘记"文档开头的约束 |
| **错误传播** | 改一处可能悄悄破坏其他地方 |
| **无法验证** | 很难知道改动是否正确 |

## 解决方案：树状结构

### 示例结构

```
project/
├── CLAUDE.md              # 🔴 全局规则（每次都会读取）
├── chapter1/
│   ├── intro.md
│   └── background.md
├── calculations/
│   ├── step1.py
│   ├── step2.py
│   └── tests/
│       ├── test_step1.py
│       └── test_step2.py
└── results/
    └── figures/
```

### 三个关键组件

**1. 根部规则文件 (CLAUDE.md)**

```markdown
## 绝对禁止
- ❌ 永远不要跳过步骤说"这变成..."
- ❌ 永远不要为了"一致性"修改已验证的结果
- ❌ 永远不要假设变量值，必须从文件读取

## 必须遵守
- ✅ 每个模块修改后，运行对应测试
- ✅ 不确定时问我，不要猜测
```

**2. 模块化文件**

每个文件只做一件事，足够小到 AI 能完全理解。

**3. 可验证性**

| 模块类型 | 验证方式 |
|----------|----------|
| 代码 | pytest |
| 公式 | 代入已知值 |
| 文章 | checklist |
| 图表 | 从源数据重新生成 |

## 实战技巧

### 1. 交叉验证
> "用 GPT 检查 Claude 的工作，反之亦然"

### 2. 反复追问
```
你: 这个对吗？
AI: 对的！
你: 请逐步验证每一行
AI: 嗯，第3行有个问题...
你: 还有吗？
AI: 第7行也有...
```

### 3. 禁止"魔法跳跃"

在规则中明确禁止：
- "这变成..."
- "为了一致性，我调整了..."
- "简化后..."

## 适用场景

| 场景 | 如何拆分 |
|------|----------|
| 写书/长文章 | 每章独立文件 |
| 科学计算 | 每步骤独立脚本 + 测试 |
| 翻译项目 | 原文/译文/审校 分开 |
| 代码重构 | 每模块独立 PR |

## 一句话总结

> **树状结构 = 大任务拆小模块 + 每个模块可独立验证 + 根部有全局规则**
