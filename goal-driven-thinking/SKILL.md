# 以终为始：为行动而思考

> **"From thinking longer to thinking in order to act."**
> 
> 从"想得更久"到"为了行动而想"。
>
> — Justin Lin (Qwen Team), 2026

---

## 核心原则

```
Thinking 的目的不是展示推理过程，而是提高最终结果的质量。
```

一切围绕解决问题而来，不是为了 thinking 而 thinking。

---

## 两种 Thinking 的区别

### Reasoning Thinking（传统）

```
输入问题 → 长链推理 → 输出答案
          ↑
    优化目标：推理链的质量
```

**关注**：能想多久？推理看起来对不对？

### Agentic Thinking（行动导向）

```
输入目标 → 计划 → 行动 → 观察 → 修正 → 行动 → ... → 达成目标
                    ↑
              优化目标：最终结果
```

**关注**：能持续有效行动吗？目标达成了吗？

---

## Agentic Thinking 必须处理的 5 个问题

| 问题 | 说明 |
|------|------|
| **1. 何时停止思考，开始行动** | 想太多不如先做 |
| **2. 选择哪个工具，什么顺序** | 工具选择是决策 |
| **3. 处理不完美的环境反馈** | 现实总是 noisy |
| **4. 失败后修正计划** | 错了就调整 |
| **5. 跨多轮保持一致性** | 记住上下文和目标 |

## 反模式 vs 正确模式

### ❌ 反模式：为 thinking 而 thinking

```
收到任务
  ↓
开始大量思考
  ↓
产生长长的推理链
  ↓
推理链看起来很聪明
  ↓
但结果不一定对
```

**问题**：
- 过度的 visible reasoning = 资源分配失败
- 更长的推理链 ≠ 更聪明
- 没有问"这个思考对结果有帮助吗？"

### ✅ 正确模式：以终为始

```
收到任务
  ↓
问：最终要交付什么？
  ↓
倒推：需要哪些步骤？
  ↓
每一步都验证：这在接近目标吗？
  ↓
直到目标达成
```

**原则**：
- 思考服务于行动
- 行动服务于目标
- 目标就是交付结果

## 实践指南

### 1. 收到任务时先问

```markdown
- [ ] 最终要交付什么？（具体产物）
- [ ] 怎么知道做完了？（完成标准）
- [ ] 用户真正需要什么？（可能和他说的不一样）
```

### 2. 行动前判断

```
这个思考/行动会让我更接近目标吗？
  ├── 是 → 继续
  └── 不确定 → 停下来重新评估目标
```

### 3. 过程中检查

```
我在解决问题，还是在展示我会思考？
  ├── 解决问题 → 好，继续
  └── 展示思考 → 停，回到目标
```

### 4. 失败时问

```
这个方向对吗？
  ├── 对，只是执行有问题 → 修复执行
  └── 方向可能不对 → 回到目标重新规划
```

## 好的思考 vs 坏的思考

> **"Good thinking" = the most useful trace for sustaining action under real-world constraints, rather than the longest or most visible one.**

| 坏的思考 | 好的思考 |
|----------|----------|
| 长 | 有用 |
| 显眼 | 有效 |
| 展示聪明 | 解决问题 |
| 产生漂亮的中间推理 | 提高最终结果质量 |

## 应用场景

### 代码任务

```
❌ 写大段注释解释要怎么做
✅ 直接写代码，跑测试，修复问题
```

### 写作任务

```
❌ 先写一页大纲的大纲的大纲
✅ 明确目标读者和核心信息，开始写，迭代修改
```

### 研究任务

```
❌ 收集所有可能相关的资料再开始
✅ 明确要回答什么问题，找最相关的资料，先给出答案再补充
```

## 一句话总结

> **Thinking should be shaped by the target workload.**
>
> **思考应该由目标任务来塑造。**

不要问"我想了多少"，要问"我解决了什么"。
