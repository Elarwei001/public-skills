# 交叉验证：用 AI 检查 AI

> AI 会"讨好用户"——调整参数让结果看起来对，而不是真正修复错误。
> 解决方案：用另一个 AI 检查。

---

## 核心原则

```
Claude 生成 → GPT 检查 → 发现问题 → Claude 修复 → GPT 再检查
```

## 为什么需要交叉验证？

### AI 的"讨好"问题

```
你: 这个图表的数据对吗？
AI: 让我调整一下参数... 现在看起来对了！
    （实际上只是让图表看起来正确，底层计算还是错的）
```

### 交叉验证能发现

- **逻辑漏洞** — 不同 AI 有不同盲点
- **假验证** — "验证通过"但其实没验证
- **魔法数字** — 硬编码让结果看起来对

---

## 实战方法

### 方法 1：直接交叉

```
1. Claude 完成计算
2. 把结果给 GPT："请验证这个计算的每一步"
3. GPT 发现问题
4. Claude 修复
5. 重复直到两边都同意
```

### 方法 2：独立计算

```
1. Claude 用方法 A 计算
2. GPT 用方法 B 独立计算同一问题
3. 对比结果
4. 不一致 → 追查原因
```

### 方法 3：角色扮演

```
在同一个 AI 中：
"现在假设你是一个严格的审稿人，找出这段代码的所有问题"
（效果不如真正的交叉验证，但聊胜于无）
```

## 检查清单模板

让检查者回答：

```markdown
## 验证清单

### 逻辑正确性
- [ ] 每一步推导都有依据吗？
- [ ] 有没有跳过步骤？
- [ ] 假设是否明确？

### 数值正确性
- [ ] 代入简单值（如 0, 1）结果对吗？
- [ ] 边界情况处理了吗？
- [ ] 单位一致吗？

### 代码正确性
- [ ] 变量名和公式中的符号对应吗？
- [ ] 有硬编码的魔法数字吗？
- [ ] 测试覆盖了主要路径吗？
```

---

## 反复追问模式

不要接受第一个"对的！"

```
你: 这个对吗？
AI: 对的！
你: 请逐行验证
AI: 嗯，第3行有个问题...
你: 还有吗？
AI: 第7行也有...
你: 确定没了？
AI: 让我再看一遍... 第12行还有一个
你: 继续
AI: 这次真的没了
你: 换个角度，从结果反推，输入输出一致吗？
AI: 等等，这里有个边界情况...
```

---

## 适用场景

| 场景 | 交叉验证方式 |
|------|-------------|
| 数学推导 | 两个 AI 独立推导，对比 |
| 代码 | AI 写，另一个 AI review |
| 翻译 | 翻译 AI + 审校 AI |
| 事实性内容 | AI 生成 + 搜索引擎验证 |

---

## 一句话总结

> **不要让同一个 AI 既做题又判卷。交叉验证 = 用不同的 AI（或不同的 prompt）互相检查。**
